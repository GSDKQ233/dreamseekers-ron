# 寻梦者 API65 repair2

此版的确切基线是上一版已交付的 `API65-repair1-source.zip`，SHA-256 `a680d639adbf9d84ca883875f53883b21a42ea6b51078533e504a10833ea612a`。原始 repair1 和任何玩家存档保持不变。

核心 `1.5.0b-ore-mines.2-dreamseekers-api.65-repair2` 和附属 `0.65.0-repair2` 必须配套；大厅和训练包发生变化，旧客户端不能和 repair2 混连。客户端和服务端同时换两个 JAR，保持四个锁定前置和原配置文件路径；升级前停服备份。

## 本批范围

| 项目 | 玩家会看到什么 |
| --- | --- |
| 阵亡英雄 | 名单跟随当前世界；同一 Minecraft 进程切换世界不会沿用上一档的名单。不会按名字猜测或删除已写入历史存档的旧记录。 |
| 原生村民携货 | 未计价物以完整物品标签写入；能计价的部分继续在结算时折入余额，不同时写进货袋。已存在的历史丢失不会补回。不是原生工人跨维度有价货物问题的完整修复。 |
| 塔防生存进度 | 保存待开始的波次、正在打的波次和最后一波是否清完。正常恢复不重发原波；旧档没有记录的活动波和奖励不猜补。清空最后一波本身不是信标胜利。 |
| 大厅 | 新进或重连时收到完整的席位、准备与倒计时快照，不重置其他玩家的客户端。已坐席玩家断开仍按旧规则退席并取消倒计时；旁观者重连不会改变真实准备状态。普通原生起点仍按既有上限；自定义地图的快照最多 1,024 席，超限不半截覆盖已有大厅。 |
| 联动训练 | 发单被拒时提示原因，已付款队首由服务端描述暂停/恢复。双手的研究院和升级世界树提示不再误写生态庭。队首身份、扣款及退款规则保留。 |
| 寻梦者信标 | 只在塔防生存中，把现有信标接入寻梦萤火虫的建造菜单；己方完成任一分支世界树升级和共鸣研究院后，可走正常建造、升级及胜利结算。费用、全图唯一、规则关闭和已预置信标的现有约束保留。未改敌方波次、PvP 或其他阵营。 |

暂不包括世界树分支收益对比、短教学、场景影能、防守胜利以外的敌方专属波次，或十轮审计里的其余优化。

## 验证

### Forge 原生 GameTest

| 范围 | 结果 |
| --- | --- |
| 阵亡英雄 | 一个 Minecraft JVM 四次完整开停服，A → 空 B → A → B，名单 1、0、1、0。 |
| 原生／联动携货 | 1 个有阶段的用例在 3 个独立进程通过：首次写盘、首重启、次重启。对照世界文件中的 UUID、物品标签和余额。 |
| 生存波次 | 1 个有阶段的用例在 4 个独立进程通过：活动波恢复、真实清波与奖励、最后波、终态再重启。波次夹具仅生成足以验证生命周期的敌人，不是完整最后一波压力测试。 |
| 大厅 | 2 项通过，覆盖新接入连接和倒计时中重连；为 Forge 内的真实包／模拟登录两端，不是两个 GUI 客户端。 |
| 训练反馈 | 3 项通过，覆盖拒绝发送对象、已付队首前置恢复、堵塞出口、只生成一次、混合队列同步与一次退款。 |
| repair1 回归 | 4 项通过，覆盖混合交货、队首身份、通信和 Shift 施工队列。 |
| 寻梦者信标 | 2 项通过：隔离场景从正常起手进入生存，完成世界树和研究院前置，实际付费建造并升五级，经过配置的持有计时后收到胜利结算；对照未完工／未知树状态、其他阵营、禁止信标和地图既有信标。测试加速了部分工程，不是完整实机对局耗时。 |

按测试进程或阶段统计：这六组的 18 次执行通过（含多阶段），另有 repair1 的 4 项定向回归。

**最终构建**：JDK 17 下 351 项 JUnit 通过，1 项原有音频用例跳过，0 失败。核心／附属的 GameTest 源码编译、发布 JAR 的重混淆、包内容及配对开发专服配置均通过。四个运行前置逐一核对锁文件。

**普通 Forge 专服（使用交付的两份 JAR，不是开发专服）**：全新测试世界和从 repair1 复制的测试世界，两条路线各完成一次启动、落盘、正常停止和重启，共 4 个 repair2 进程。比对了旧测试世界方块、命令存储值及实体 UUID，以及新写入的飞萤 UUID；原 repair1 测试世界未改。旧测试世界是合成样本，不是一般玩家世界迁移的承诺。

### 仍未验证

两个真实图形客户端的操作与布局、真实玩家世界或非正常断电的存档一致性，均不由上述结果替代。历史版本没有记录的物品、英雄归属或已经领取过的生存奖励没有自动修复。
