# API65 repair3.1 验收候选

本候选以资料库 `API65-repair3-source.zip` 为基准，原包 SHA-256 为
`226856fca5f3e9eb7da58f1e190e8863dbba77036480d59a4149c9bf71ea5ef2`。
核心 `1.5.0b-ore-mines.2-dreamseekers-api.65-repair3.1` 和附属 `0.65.0-repair3.1` 必须配对，
客户端与服务端不得跨版本混装。运行环境为 Minecraft 1.20.1、Forge 47.4.0 和 Java 17。

## 修正范围

- 生产队列客户端收包逻辑移到独立的客户端处理类；专服注册公共封包时不再校验客户端类型。
  封包字段、方向、队列状态处理和现有连接校验不变。版本标记会隔离旧候选。
- 保留波斯语文件，不增补翻译，不以条数或逐键覆盖作为验收门槛。继续检查资源解析及译文结构，
  使用真实客户端语言加载器和缺译测试样本验证英文回退，并检查变更涉及的中英文关键提示。
- 不改变存档格式、玩法、数值或客户端语言文件。不新增对真实玩家存档迁移或断电一致性的承诺。

## 发布前检查

1. 在最终候选运行 Java 17 全量单元测试并编译两套 Forge 测试源码。
2. 在隔离世界按 [repair3 修复说明](REPAIR3.zh-CN.md) 的阶段顺序重新运行关键 Forge 回归。
3. 核对实际配对 JAR 的版本和依赖；用普通专服检查冷启动、保存和重启。旧版对照使用独立合成存档。
4. 对同一配对版本用两个独立图形客户端验收入席与重连、同配方撤单、科研暂停和 HUD。
   服务端或自动化测试不能替代图形客户端的验收。

源码不是稳定 API 或可安装发行包。历次测试仅对应当时的确切源码和成品，不可移记。

## 已验证与未验证

- 两份实际重混淆 JAR 均通过内容、CRC、版本与精确配对依赖校验；未把四个前置模组、测试夹具或日志装入交付包。
- 普通 Forge 运行了 8 个独立专服进程：1 个原 repair2 对照、1 个 repair3.1 核心单装、
  新世界／repair2 合成副本／非空未锁定名单各 2 个 repair3.1 配对进程。均正常保存并退出。
  合成升级对照的方块、存储及单位 UUID 保留；两席名单和开放状态保留。这不等于已验证新玩家登录。

  `1 / 2 ready`。没有修改任何波斯语翻译，也没有把开发客户端主界面计作正式双端试玩。
